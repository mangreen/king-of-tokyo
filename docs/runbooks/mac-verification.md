### 已發現並修正的環境問題

1. **esbuild 在 Big Sur 無法安裝。** esbuild 0.27 起的 macOS 二進位檔最低需要 macOS 12。已固定 tsx 4.20.6、tsup 8.5.0（相容 esbuild 0.25.12），並用 `pnpm run check:baseline` 防止回退。
2. **Snyk 容器掃描的高風險項目不是我們的程式碼**，而是舊映像裡的 pnpm／npm。runtime 映像已改成不帶套件管理器。
3. Snyk CLI 在 Big Sur 會印出 `dyld: Symbol not found` 與 degraded 警告，但掃描本身可以完成，訊息可以忽略。

```bash
git fetch origin && git checkout main && git pull
pnpm install --frozen-lockfile
pnpm run check            # 預期全部通過，最前面印出「基準機相容性檢查通過」
                          # （規則 283、協定 29、卡牌組 19、房間 64、網頁 162、伺服器 70 個測試）

curl http://localhost:3001/healthz   # 預期 {"status":"ok"}
```

正式 server 映像只含原創卡組、不含套件管理器：

```bash
docker build --target server -t kot-server .
docker run --rm kot-server ls /app/card-sets        # 預期只有 original
docker run --rm kot-server sh -c 'which npm pnpm yarn corepack || echo "沒有套件管理器（預期）"'
```

依賴掃描（Snyk CLI 在 Big Sur 只能降級執行；任選一種）：`snyk container test kot-server`、`snyk test --all-projects`、`pnpm audit --prod`，或在 Snyk 網站匯入 GitHub repo。沙盒的 `pnpm audit --prod` 目前有 4 個既有的警告（`@fastify/static` 有 1 個 high、`glob`），請一併回報你那邊的結果。

單一容器的試玩版 image 見 [cloud-run-demo.md](cloud-run-demo.md)（`make demo-image`）。

### B. 伺服器模式的基本流程（M2、M3、M4.12）

瀏覽器開 http://localhost:5173，用兩個視窗（其一用無痕視窗，因為身分存在 sessionStorage）：

1. 視窗 A 輸入暱稱 → 建立房間（可選卡牌組），記下 5 碼房號；視窗 B 輸入另一個暱稱 → 用房號加入 → 按「準備」；A 按「開始遊戲」。預期：兩邊都看到玩家表、東京市、倒數計時；輪到的人可以「擲骰／重擲／結算」，點骰子可保留。
2. **重連：** 對局中在 B 按重新整理。預期：回到同一座位的對局畫面，商店與持有卡牌仍在（事件日誌會是空的，這是預期行為）。
3. **逾時代打：** 輪到某位玩家時什麼都不做，等 45 秒。預期：標示「代打中」；之後那位玩家再按任何合法動作就會取回控制。
4. **斷線：** 對局中關掉 B 的分頁。預期：A 看到 B「離線」，輪到 B 時約 1.5 秒就被代打。
5. **卡牌（M3）：**
   - 商店有 3 張牌，顯示名稱、費用、卡面文字；買不起的牌沒有「買」按鈕。
   - 擲骰結算後進入「買牌階段」，可以買牌、花 2 能量清掉商店、結束回合。
   - 買到 Keep 卡後出現在玩家表格的「卡牌」欄，滑鼠移上去看得到文字；有主動能力的卡出現「使用…」群組。
   - 被攻擊時，會依狀況出現讓位、防禦反應、治療分配等提示。
   - 事件日誌顯示卡牌名稱（不是 id）。
6. 自備卡表（選配）：把 CSV 放進 `card-sets/local/`、執行 `pnpm --filter @kot/cardsets run import`、重啟 server，建房時會多一個選項。
7. **邀請連結（M4.12）：**
   - 房主在房間頁按「複製連結」，貼到別處確認是 `https://網址/?room=房號`；手機上按「分享…」能叫出系統分享選單。
   - 另一台裝置（或無痕視窗）開連結：看到「你被邀請加入房間 XXXXX」，輸入暱稱後直接進入房間，房主那邊立刻看到新玩家。
   - 加入後網址上的 `?room=` 消失；重新整理仍在房間內。
   - 連結的房間已開始遊戲、已滿或不存在：回到大廳並顯示原因，不會卡住。
   - 已經登入的分頁開邀請連結：直接加入（若本來就在別的房間內則不動）。
8. 手機同一個 Wi-Fi（選配）：把 `.env` 的 `ALLOWED_ORIGINS` 加上 `http://<你的 Mac 區網 IP>:5173`，並把 `VITE_SERVER_URL` 改成 `http://<IP>:3001`，用手機瀏覽器開。

### C. 3D 場景與介面（M4 系列）

請回報瀏覽器名稱與版本；在 `chrome://gpu`（Chrome）或 `about:support`（Firefox）確認是否硬體加速、GPU 與 WebGL2 最大紋理尺寸。

**3D 場景（M4）**

1. 開 http://localhost:5173/?scene-demo（離線展示頁，不需要伺服器）：看得到東京灣場景——西側市區與東京鐵塔、東側海面、彩虹大橋、台場的摩天輪；用按鈕觸發攻擊、淘汰、護盾等演出。
2. 在展示頁把畫質切到「高」，觀察 FPS 與 draw calls（頁面上的統計）。**基準機目標 ≥ 30 FPS**；回報高／中／低各自的 FPS。自動畫質應只在掉到 26 FPS 以下時降級。
3. 兩個瀏覽器視窗打一整局：怪獸在環形座位與東京市／東京灣之間移動；扣血、淘汰在撞擊時才反映到名牌；3D 骰子滾到伺服器決定的點數。
4. 「跳過動畫」立即套用最終狀態；切到別的分頁再回來不會卡住；關閉「鏡頭動態與震動」後沒有鏡頭運動。
5. 系統設定開啟「減少動態」時，鏡頭動態預設關閉且勾選框停用。
6. 按「關閉 3D」後遊戲仍可完整操作；重新整理後偏好還在。
7. 風扇聲、發熱、卡頓、畫面破圖（貼圖或陰影）、建築擋住怪獸的情況。

**3D 區內 HUD（M4.5）**

1. 3D 區上方有狀態列（房號、輪次、誰的回合、倒數、「🏁 20 VP」與四個分頁），左側玩家清單，下方是骰子與操作。
2. 玩家持有的卡牌是小標籤：滑鼠移上去顯示完整說明；點一下可固定、再點關閉；Tab 聚焦也會顯示、Esc 關閉。
3. 擲骰區「❓ 結算規則」可展開／收起；骰子下方有「若現在結算」的預覽（例如 3 顆 2 → +2 VP）。
4. 「🏁 20 VP」移上去／點一下看到勝利條件；事件分頁的「🏁 勝利條件」可展開；規則分頁有每位玩家的 VP 進度與完整規則。
5. 輪到你買牌時商店自動展開，可買的牌有按鈕；清商店按鈕也在商店裡；「我的卡牌」列出完整說明。
6. 縮小瀏覽器寬度到 1000px 以下：HUD 改成排在場景下方，功能相同。
7. 「全螢幕」按鈕：場景與 HUD 一起放大，Esc 離開。
8. 若有觸控裝置（iPad／手機）：點卡牌標籤開關說明、長按也能開；點別處關閉。
9. 「關閉 3D」後，同一份 HUD 排在頁面裡，仍可完整操作。

**地圖視角（M4.6、M4.7 與跟隨按鈕修正）**

1. 寬螢幕：地圖在左、操作面板在右，兩者不重疊；縮小視窗到直向（或用手機／平板）時，地圖固定在最上方、面板在下方捲動，怪獸與名牌始終看得到。
2. 地圖：滑鼠拖曳移動、滾輪縮放（以游標為中心）、右下角 ＋／－ 按鈕；調整後出現黃色 ↺，點它或雙擊地圖回到預設並恢復自動鏡頭。
3. 觸控（iPad／手機）：單指拖曳、雙指縮放；在地圖上拖曳時頁面不會跟著捲動（要捲頁面請觸碰面板區）。
4. 鍵盤：Tab 到地圖後方向鍵移動、+／- 縮放、0 重置。
5. 調整視角後打出攻擊：畫面不會被自動鏡頭搶走；重置後自動鏡頭恢復。
6. 手感：拖曳是否「黏手」、縮放是否過快或過慢、縮到最小／最大時是否合理。
7. 全螢幕：地圖與面板一起放大。
8. **鏡頭跟隨：** 輪到某隻怪獸時鏡頭平滑移到它身上並拉近，換人時移到下一隻；怪獸進入／離開東京、攻擊時演出鏡頭照常切入，結束後回到跟隨。
9. 地圖右下 🎯（或 🎥）與下方「鏡頭跟隨行動中的怪獸」可關閉；系統開啟「減少動態」時不跟隨（選項停用）。感受：移動是否太快或太慢、拉近倍率是否合適、會不會頭暈。
10. **跟隨按鈕狀態：** 開著跟隨（綠色）時拖曳／縮放地圖：按鈕變成灰底綠色虛線框（暫停），出現 ↺。此時按它：視角重置、鏡頭回到跟隨、變綠，不會被關掉；按 ↺ 也會重置並回到跟隨。在綠色狀態再按一次才是關閉（灰色）；下方勾選框行為相同。

**提示與商店（M4.8）**

1. 買牌階段輪到你、買得起牌：畫面下方跳出「商店有 N 張牌買得起」，按「看商店」打開商店（手機會捲到商店區）。
2. 商店還有買得起的牌時，沒有「結束回合」按鈕，只有橘色「🚪 離開商店」；按下後才出現「結束回合」。買不起任何牌時直接是「結束回合」。
3. 重大事件提示：輪到你、重擊（≥4 傷害）、你的 HP ≤3、有人進入東京／被淘汰、有人離勝利只差 5 VP 或達標、有人買牌、你中毒。擲骰、回復、能量這類小事不會跳。
4. 提示 4–9 秒自動消失，可點 ✕ 關閉，最多同時 4 則；系統「減少動態」時沒有滑入動畫。
5. 地圖右下的攝影機圖示：綠色＝跟隨開、灰色＝關。
6. 感受：提示是否太多／太少、停留時間、位置有沒有擋到操作。

**站位與招式特效（M4.9）**

1. 6 人對局：怪獸圍成一圈，東京鐵塔那一側是空的；從總覽鏡頭與跟隨鏡頭看，沒有怪獸被鐵塔、彩虹大橋、摩天輪擋住。2–5 人也各看一次。
2. 招式特效：蜥蜴＝青色吐息、猿＝搥地裂痕與碎石、機械＝紅色雷射、章魚＝紫色墨汁鞭、螃蟹＝白色爪痕、龍＝噴火。同時打到多個目標時每個目標都有落點效果。
3. 場景下方取消「怪獸招式特效」：攻擊時只剩原本的衝撞與命中效果；再勾回來立即生效，重新整理後仍記得。
4. 系統開啟「減少動態」：招式特效預設關閉，仍可手動打開。
5. 基準機：連續多次重擊（尤其龍噴火、猿搥地）時 FPS 是否維持 ≥30；若掉很多，回報是哪一種招式。

**怪獸造型隨機分配（M4.10）**

1. 同一個房間連玩幾場：每場每位玩家的怪獸不同，同一場內不重複；所有玩家看到的同一個人是同一隻怪獸。
2. 玩家列表每個人名字旁顯示怪獸名稱，與 3D 場景中的造型相符。
3. 12 種造型都至少出現一次：外型辨識度、大小是否一致、名牌位置是否正常；從總覽與跟隨鏡頭看都沒有被建築擋住。
4. 12 種怪獸各攻擊一次，招式特效都正常（含水柱、鐮刀斬、冰霜、震地、孢子、凝視光束）。
5. 基準機：6 人局抽到面數較多的造型時 FPS 是否仍 ≥30。

### D. 電腦玩家與閒置踢除（M4.13、M4.14）

**電腦玩家**

1. 建立房間後，房間頁只有房主看得到「🤖 加入電腦」；按一下多一位「電腦 N」（有 🤖 標籤、已準備），旁邊有「移除」。真人加電腦滿 6 位時按鈕變灰。
2. 只有房主一人時「開始遊戲」是灰的；加一台電腦就能開局。非房主（用邀請連結加入的朋友）看得到電腦但沒有加入／移除按鈕。
3. 開局後輪到電腦時：約 1.4 秒後自動擲骰、保留骰子、重擲、結算、買牌；3D 演出跟得上、不會一次噴出一堆動畫。玩家列表有 🤖 標籤，沒有「代打中」，也沒有倒數秒數。
4. 電腦在東京被打時會自己決定讓位；血量低時傾向離開。
5. 你自己閒置：你被標成「代打中」（用較弱的固定策略），電腦不受影響。
6. 只剩電腦（真人都離開）時房間會關閉，不會留下一場沒人看的對局。
7. 多打幾場：電腦是否「看起來合理」（不會自殺式亂買牌、不會一直待在東京被打死）；有任何明顯不合理的決定請記下局面回報，這些會是調整 `ai.ts` 權重的依據。
8. 基準機：對局中有電腦時 FPS 與沒有電腦時相比有無差異（伺服器模式下電腦的計算在伺服器，網頁端不應受影響）。

**閒置踢除**

1. 登入後把分頁丟著不動（試玩版 5 分鐘、本機預設 10 分鐘）：畫面出現「閒置太久，已中斷連線」與「重新連線」「登出」兩個按鈕，**不會自動重連**。
2. 按「重新連線」：回到原本的房間／座位（對局中也一樣）。
3. 一直有操作（移動滑鼠、轉動鏡頭）超過上限時間：不會被踢。
4. 分頁切到背景超過上限：被踢（預期行為）；切回來看到「重新連線」。
5. 對局中閒置被踢：你的角色由代管接手，其他人照常進行。
6. Cloud Run：部署後放一天，看「容器執行個體時間」與「請求數」是否比以前低（以前沒有基準，只能看是否不再爆表）。

### E. 離線模式與房主模式（M5、M6，見 [ADR-0007](../adr/0007-p2p-host-authoritative.md)）

**離線模式（M5）**

1. 開 `http://localhost:5173/?offline=1`：頁面上方有「離線模式」提示。**停掉 server（`docker compose stop server`）後也能用**：輸入暱稱、建立房間、加入 2 個電腦玩家、開始遊戲，一路玩到結束。
2. 開瀏覽器開發者工具的 Network：**沒有 WebSocket 連線**，也沒有對 server 的請求。
3. 離線局中重新整理頁面：回到登入畫面（這局結束），**不會**自動接回（預期行為，M8 才做接回）。
4. 基準機：離線模式 6 人局（1 真人＋5 電腦）的 FPS 與 CPU；電腦玩家的計算在 Worker，畫面應該不會因為電腦思考而卡住。
5. 手機瀏覽器開同一個離線網址試玩，回報是否能完整玩完一局。

**房主模式（M6，需要 server 在跑）**

1. 開 `http://localhost:5173/?mode=p2p`：頁面上方有「房主模式」提示。輸入暱稱、**房號欄留空**、按「當房主」→「建立房間」，房間頁出現分享連結。
2. 用**另一個瀏覽器（或無痕視窗）**開分享連結，輸入暱稱加入。兩邊都看得到彼此；房主按「加入電腦」，雙方準備後開始遊戲。
3. 玩一局：兩邊的畫面同步；Network 面板：房主與客人各有**一條** WebSocket 連到 server，**沒有**其他連線；房主在建立房間之前沒有連到 server。
4. 客人重新整理頁面：回到登入畫面（預期，M8 才做接回）；用同一個連結重新加入，房間還在。
5. 房主關閉分頁：客人約 30 秒後看到連線結束的提示。
6. 用手機開分享連結當客人，回報是否能完整玩完一局，以及延遲感受（多一跳經過 server）。
7. （選配）房主用手機：回報螢幕關閉或切到別的 app 後，房間是否中斷。

### F. 直連（WebRTC，M7，見 [ADR-0007](../adr/0007-p2p-host-authoritative.md)）

需要 server 在跑，並用房主模式（`/?mode=p2p`）。預設用 Google 的 STUN 查詢公開位址（對方會看到你的 IP）；不想用就在建置／啟動前端時設 `VITE_ICE_SERVERS=`（空字串，只能區網直連），或網址加 `&direct=0` 完全關閉。

1. 房主與客人用**同一個區網**的兩台電腦（或同機兩個分頁）：進房後房主模式提示下方出現連線方式，幾秒內客人顯示「與房主直連」、房主顯示「1 位玩家直連」。
2. 開發者工具 Network → WS：直連建立後**客人的 WebSocket 連線關閉**；房主按「開始遊戲」後**房主的也關閉**（連線方式出現「伺服器連線已暫停」）。整局打完不應再出現新的 WebSocket。
3. 對局中兩邊畫面保持同步，操作沒有明顯延遲（直連應比經 server 更快）。
4. 客人關閉分頁：房主約 15–30 秒後回到「經伺服器轉送／沒有其他玩家」，Network 出現新的 WebSocket（房主回到中繼）。
5. **跨網路**：客人用手機（行動網路）、房主用電腦（家用 Wi‑Fi）：回報是否顯示「與房主直連」；若一直顯示「經伺服器轉送」代表兩端 NAT 太嚴格連不上（預期可能發生，沒有 TURN），此時對局應該照樣能玩完（經 server 轉送）。
6. 網址加 `&direct=0`：全程走伺服器轉送，行為與 M6 相同。
7. 回報：瀏覽器與版本（Safari、Firefox、手機瀏覽器特別需要）、是否直連成功、停泊期間（連線方式顯示「連線已暫停」）放置 10 分鐘以上房間是否還在。
