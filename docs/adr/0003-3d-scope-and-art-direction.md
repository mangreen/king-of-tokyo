# ADR-0003：3D 範圍與美術方向

- 狀態：已採用（2026-11-05）；細節在 M4 前再審視

## 背景

使用者希望做成「3D 遊戲」，風格參考兩個來源：

1. 桌遊封面與卡牌：美漫卡通、粗黑描邊、放射狀速度線、高飽和色。
2. 影片 https://youtu.be/fSM27EaZVM0（IGN 發布的《Godzilla: Destroy All Monsters Melee Remastered》上市預告，約 2026-11-03）。

使用者在 2026-11-05 確認方向為**融合**：卡通怪獸造型，搭配電影級鏡頭、破壞與煙塵特效。最想要的是：**怪獸踩踏、拳拳到肉的打擊感、建築倒塌、鏡頭運鏡、對戰特效**。

> 註：影片本身我無法實際觀看（YouTube 擋掉自動讀取，只取得標題與描述），以上方向來自使用者的文字說明，不是對影片畫面的分析。

## 決策

**Three.js 負責場景與演出，DOM 負責資訊。**

| 範疇       | 方式                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| 東京場景   | 低多邊形城市街區（東京市／東京灣兩個位置），建築為可破壞的模組化區塊                 |
| 怪獸       | 卡通風 3D 或面向鏡頭的立繪（billboard）+ 骨架／程序動畫，M4 初期以後者降低美術成本   |
| 打擊感     | 命中停頓（hit-stop）、鏡頭震動、衝擊波環、碎片與煙塵粒子、受擊閃白、數字彈出         |
| 建築倒塌   | 預先切好的碎塊 + 簡單的拋物線／重力模擬，**不引入完整物理引擎**                      |
| 鏡頭       | 預設全景；攻擊、進入東京、淘汰等事件觸發的短鏡頭（推近、環繞、慢動作），可由玩家關閉 |
| 3D 骰子    | 結果由伺服器決定，動畫只負責「滾到指定面」，不用物理引擎                             |
| 卡牌與 HUD | DOM + CSS（左上能量圓標沿用卡面辨識度），可讀性與無障礙較好                          |

**所有演出都是對伺服器事件的「回放」**：規則引擎輸出事件列表（例如 `smash`、`yield`、`eliminated`），客戶端依序播放動畫。動畫只影響呈現，不影響遊戲狀態，因此可跳過、加速或在低畫質下簡化。

## 效能預算（以 2014 MacBook Pro 13"：雙核 i7、Intel Iris 內顯為基準機）

- 目標 ≥30 FPS；draw calls < 100；三角面 < 10 萬；DPR 上限 1.5（低畫質為 1.0）。
- 首次載入 JS < 1.5 MB gzip；貼圖總量 < 64 MB。
- 低畫質模式：關閉後處理、減少粒子與碎片數量、縮短鏡頭演出；依 frame time 自動降級。
- 預算是否達成**必須在你的實機上量測**，雲端沙盒沒有 GPU，無法代替。

## 素材與 IP

- 怪獸、卡面、場景一律使用**原創設計**；只借鏡風格與運鏡手法。
- 《King of Tokyo》的角色與卡圖屬於 IELLO 等權利人，《哥吉拉》及其角色屬於東寶。即使是私人遊玩，也不把這些素材放進專案。
- 官方卡牌的名稱與文字見 [ADR-0004](0004-swappable-card-sets.md) 的處理方式。

## 影響

- 規則引擎必須輸出**結構化事件**，不能只輸出最終狀態（M1 的設計約束）。
- M4 才投入大量美術與特效；M0–M3 的 UI 刻意保持簡陋，專注於規則與連線的正確性。
- 若基準機達不到預算，優先降低特效密度，而不是放寬預算。
