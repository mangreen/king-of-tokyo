# ADR-0003：3D 範圍與美術方向

- 狀態：已採用（2026-11-05），**2026-11-06 依使用者提供的遊戲截圖修訂**；細節在 M4 前再審視

## 背景

使用者希望做成「3D 遊戲」，風格參考兩個來源：

1. **桌遊封面與卡牌**：美漫卡通、粗黑描邊、放射狀速度線、高飽和色。
2. **《Godzilla: Destroy All Monsters Melee Remastered》**（影片 https://youtu.be/fSM27EaZVM0，IGN 上市預告；YouTube 擋掉自動讀取，所以我改看使用者在 2026-11-06 提供的 6 張遊戲截圖）。

使用者最想要的是：**怪獸踩踏、拳拳到肉的打擊感、建築倒塌、鏡頭運鏡、對戰特效**。

### 從截圖觀察到的特徵

| 畫面           | 觀察                                                                                                                   | 對我們的意義                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 高角度城市全景 | 建築是簡單的方塊，以重複的窗格貼圖組成；樹列街道、小車輛；倒塌的建築變成瓦礫堆並冒煙；兩隻巨獸對峙；畫面邊緣有輕微暈影 | **場景用簡化的模組化建築**，細節留給怪獸與特效。瓦礫會留在場上，形成「破壞進度」 |
| 低角度英雄鏡頭 | 怪獸頂天立地；橘褐色的大團煙塵、飛散的碎塊、暖色霧化天空、強輪廓光                                                     | 事件鏡頭：低角度、廣角、暖色塵霧                                                 |
| 舉起／砸毀建築 | 怪獸舉起一棟建築；碎塊與煙霧飛散；紫色電弧；背景有青藍色六角形能量屏障                                                 | 破壞動畫；**六角形屏障**適合做防禦／無效傷害類事件；電弧適合能量類特效           |
| 夜景叢林峽谷   | 深藍色調、河流、岩柱上的科幻建築；飛行的怪獸                                                                           | 之後可加入其他場地主題（M6 選配）                                                |
| 正面特寫       | 廣角近距離、戲劇光、發光的眼睛、翅膀                                                                                   | 角色登場／淘汰時的特寫鏡頭                                                       |
| 整體           | 場景簡單、角色精細（皮膚／鱗片有明顯的法線細節）、冷暖對比的調色                                                       | 把效能預算花在**角色與特效**，不是場景                                           |

## 決策

**分工：3D 場景跟截圖（半寫實），UI 跟桌遊封面（卡通）。**

- 3D 場景採「**風格化寫實**」：簡化的建築、精細度適中的怪獸、電影感的鏡頭與破壞特效。
- UI（HUD、卡牌、大廳、勝利畫面）沿用桌遊封面的卡通語言：粗黑描邊、放射狀速度線、高飽和色、左上角能量圓標。這同時滿足兩個參考來源，也讓資訊的可讀性不受 3D 場景影響。

**Three.js 負責場景與演出，DOM 負責資訊。**

| 範疇           | 方式                                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 東京場景       | 模組化建築以 `InstancedMesh` + 貼圖圖集繪製（整片街區約 1 個 draw call）；建築倒塌時，該實例換成瓦礫模型並噴出煙塵與碎塊；瓦礫留在場上直到遊戲結束 |
| 怪獸           | **原創設計**，中等面數（目標 15–25k 三角面）、烘焙法線貼圖；同時只有 2–3 隻在鏡頭內。低畫質改用較低的 LOD                                          |
| 踩踏           | 腳步落地：地面煙塵環、裂痕貼花、輕微鏡頭震動                                                                                                       |
| 打擊感         | 命中停頓（hit-stop，約 60–120ms）、鏡頭震動、衝擊波環、受擊閃白、傷害數字彈出、碎塊與煙塵                                                          |
| 煙塵           | **粒子貼圖（billboard sprite）**，橘褐／灰色，柔邊透明；不做體積光或體積霧。粒子上限：高畫質約 300、低畫質約 100                                   |
| 碎塊           | 約 60 塊（低畫質約 20 塊）實例化，簡單的拋物線重力模擬；**不引入物理引擎**                                                                         |
| 護盾與能量特效 | 六角形圖樣的 shader 平面（防禦、無效傷害）；紫色電弧用 sprite（能量、攻擊）                                                                        |
| 鏡頭           | 預設高角度全景；事件觸發的短鏡頭（低角度英雄鏡頭、推近、環繞、特寫），可由玩家關閉                                                                 |
| 場地           | M4：東京市（日景，暖色塵霧）、東京灣（水岸，冷色調）。其他主題（如夜景峽谷）列入 M6 選配                                                           |
| 3D 骰子        | 結果由伺服器決定，動畫只負責「滾到指定面」，不用物理引擎                                                                                           |
| 卡牌與 HUD     | DOM + CSS                                                                                                                                          |

**所有演出都是對伺服器事件的「回放」**：規則引擎輸出事件列表（例如 `smash`、`yield`、`eliminated`），客戶端依序播放動畫。動畫只影響呈現，不影響遊戲狀態，因此可跳過、加速或在低畫質下簡化。

### 與卡牌的對應（M3/M4 時處理）

卡表裡有許多「+N 勝利點」的 Discard 卡（Apartment Building、Skyscraper、Amusement Park 等）。它們可以對應成**摧毀一棟對應類型的建築**，讓分數的來源和場上的破壞同步。這是設計構想，不是已確認的需求。

## 效能預算（以 2014 MacBook Pro 13"：雙核 i7、Intel Iris 內顯為基準機）

- 目標 ≥30 FPS；draw calls < 100；三角面 < 10 萬；DPR 上限 1.5（低畫質為 1.0）。
- 首次載入 JS < 1.5 MB gzip；貼圖總量 < 64 MB。
- 預設不開後處理；暈影用 CSS 疊層；陰影只用一盞方向光、低解析度（低畫質改為腳下的假陰影）。
- 低畫質模式：減少粒子與碎片數量、降低怪獸 LOD、縮短鏡頭演出；依 frame time 自動降級。
- 截圖中的遊戲是為主機與 PC 做的，畫質無法直接對標。**取捨原則：預算優先，特效密度與模型精細度先降。**
- 預算是否達成**必須在你的實機上量測**，雲端沙盒沒有 GPU，無法代替。

## 素材與 IP

- 怪獸、卡面、場景一律使用**原創設計**。截圖只作為「渲染方式、特效與鏡頭語言」的參考，**不是角色設計的參考**：不複製既有怪獸的輪廓或標誌性特徵。
- 《King of Tokyo》的角色與卡圖屬於 IELLO 等權利人，《哥吉拉》及其角色與該遊戲的畫面屬於各自的權利人。
- **repo 目前是公開的（之後會轉私人）。截圖與任何第三方素材都不提交到 repo。** 轉私人後，公開期間已存在的 commit 歷史仍可能被他人複製，所以這條規則在轉私人前後都適用。
- 官方卡牌的名稱與文字見 [ADR-0004](0004-swappable-card-sets.md) 的處理方式。

## 影響

- 規則引擎必須輸出**結構化事件**，不能只輸出最終狀態（M1 的設計約束）。
- M4 才投入大量美術與特效；M0–M3 的 UI 刻意保持簡陋，專注於規則與連線的正確性。
- 美術成本集中在**怪獸模型**（原創，最耗時）與**特效**。**決議（2026-11-06，使用者）：怪獸模型先由我以程式碼產生（程序化原創模型）**，用基本幾何組合出造型、剔除多餘細節以符合預算；之後若使用者提供或另行取得模型，只替換模型檔，不影響規則與事件。程序化模型達不到截圖那種「皮膚／鱗片細節」，風格差距在 M4 前先對齊期待。
- 若基準機達不到預算，優先降低特效密度，而不是放寬預算。
