# King of Tokyo（網頁多人連線 3D 版）

私人專案：把 King of Tokyo 桌遊做成可與朋友連線遊玩的網頁遊戲，最終目標是 3D 演出。伺服器權威、回合制，2–6 人。

## 目前可以做什麼

- 在瀏覽器輸入暱稱（不需註冊）→ 建立房間或用 5 碼房號加入 → 準備 → 開始。
- 打完整局規則：擲骰與重擲、能量／治療／攻擊、東京市與東京灣、讓位、淘汰、勝負判定（20 VP 或最後存活，支援多勝者）。
- **能力卡：** 商店三張牌、買牌、花 2 能量清掉商店、持續（Keep）與一次性（Discard）卡、使用卡牌能力、被攻擊時的防禦反應、治療分配、復活與搭檔共同勝利。建房時可選卡牌組（原創卡組；若放了自備卡表則多一個選項）。
- **向別人買牌（寄生觸手）與牌庫頂（先知）都在商店分頁（M4.20）：** 這兩種購買會列在商店分頁、附卡面文字，並計入「商店有 N 張牌買得起」提示、分頁徽章與「離開商店」；以前只藏在動作區、沒有說明。
- 斷線可回來接回同一座位；逾時由系統代打（代打不買牌、不使用能力）。
- **3D 戰場（M4）：** 真實東京灣配置的場景——東京鐵塔、晴空塔、彩虹大橋、台場（摩天輪）、隅田川、東京灣；原創的程序化怪獸（12 種造型，每場開局由伺服器隨機、不重複地分配給玩家）、踩踏／打擊感／淘汰／護盾特效、事件鏡頭、3D 骰子。所有演出都是伺服器事件的回放，可跳過；畫質可自動降級，也可關閉 3D（沒有 WebGL 時自動退回純 DOM 介面）。
- **3D 區內完整操作（M4.5）：** 玩家、擲骰與動作、商店、事件、規則、我的卡牌都在 3D 區內，而且**不遮住地圖**——寬螢幕／橫向是「地圖在左、面板在右」，直向（手機／平板）是「地圖固定在上方、面板在下方捲動」；也可全螢幕。玩家持有的卡牌可用滑鼠移上去、點一下或長按（觸控）、鍵盤聚焦查看完整說明；擲骰區可展開「結算規則」並即時預覽這組骰子的收益；「🏁 勝利條件」可在狀態列、事件與規則面板查看。沒有 3D 時同一份 HUD 排在頁面裡。
- **地圖可拖曳縮放（M4.6）：** 滑鼠拖曳移動、滾輪縮放（以游標為中心）；觸控單指拖曳、雙指縮放；也有 ＋／－ 按鈕、方向鍵與 +/-/0，雙擊或 ↺ 重置。調整視角時暫停自動鏡頭，重置後恢復。
- **鏡頭跟隨（M4.7）：** 輪到哪隻怪獸行動，鏡頭就平滑地移過去並拉近（方位不變、地圖不旋轉）；攻擊、踩踏等演出仍會切到演出鏡頭，演出結束回到跟隨。可用地圖右下的 🎥（綠色＝跟隨中、灰色＝關、綠色虛線框＝你調整了視角而暫停，點一下重置視角並回到跟隨）或下方「鏡頭跟隨行動中的怪獸」開關；「減少動態」或手動調整視角時不跟隨。
- **提示（M4.8）：** 買牌階段輪到你且買得起牌時跳出「商店有 N 張牌買得起」（可直接前往商店；數字跟著現在買得起的張數即時更新，買到沒能量、按過「離開商店」或離開買牌階段就收掉）；提示不分敵我，圖示表示結果從哪來：**🎲 骰子**（誰補了多少 ♥️、誰對東京裡／外的所有怪獸發動幾點攻擊、誰得到幾點 ⭐、誰得到多少 ⚡；在東京裡擲出 ♥️ 也會說明不能補血）與 **🃏 卡牌**（誰使用／發動了哪張牌、造成什麼結果、誰購買了哪張牌；買下立刻生效的牌——流星雨之類的一次性牌、最大 HP＋2 等——購買提示之後會再跳一則「【卡名】生效：誰的 HP／⭐／⚡ 變多少」）。**偷看牌庫頂**（先知）會跳 🔮 提示並停留 12 秒，內容是看到的那張牌的費用與卡面文字，整個買牌階段商店分頁也會留著這張牌；改骰、讓位換卡、用 ❤️ 解除指示物、清掉商店、卡用完被棄掉這些原本只出現在事件日誌的卡牌事件也都有提示。其他重大事件（輪到你、淘汰、自己血量見底、進入東京、有人接近或達到勝利分數、中毒…）同樣會提示，單純的擲骰過程留在事件日誌。全螢幕時提示會掛進全螢幕元素（掛在 body 的話全螢幕下看不到）。商店還有買得起的牌時，「結束回合」會先換成橘色的「🚪 離開商店」，按過才出現「結束回合」，避免不小心直接結束。
- **座位避開大型建物＋招式特效（M4.9）：** 怪獸環形站位會避開東京鐵塔擋住視線的那一段弧，並用「障礙盒」檢查（鐵塔、晴空塔、彩虹大橋橋面與塔、摩天輪、電視台大樓）確認從總覽鏡頭與跟隨鏡頭看，每個座位都不會被擋到。每種怪獸造型有各自的攻擊招式——蜥蜴能量吐息、猿搥地、機械雷射、章魚墨汁鞭、螃蟹爪擊、龍噴火（原創、純視覺，傷害仍由伺服器決定）；可在場景下方取消勾選「怪獸招式特效」關閉（系統「減少動態」時預設關閉）。
- **商店飛碟＋卡牌特效（M4.10）：** 輪到某人的買牌階段、而且買得起商店裡的牌時，一架原創飛碟（淡紫碟身、藍玻璃罩、黃燈、閃電徽章）就從畫面右上飛入並停在城市上空，打出黃色光束，光束裡飄著商店翻開的牌；買到的那張飛向買家、補進的新牌滑進光束；花 2 能量清商店時舊牌被吸回碟身、換上新牌；買不起任何牌、但付得起 2 能量清商店時，飛碟照樣入場，光束裡改飄一個慢慢旋轉的 ♻ 更新圖示（不是卡片，提醒可以清商店；買得起時圖示淡出、牌滑進來）；買牌階段結束或連清商店都付不起，飛碟就往左上飛走（輪到別人時，商店要持續開著超過 1.5 秒才飛來，避免機器人一閃而過的買牌窗口讓飛碟飛進飛出、光束忽明忽暗；飛碟是否在場只看商店當下買得起或清得起，不會被前面還在演的特效佇列卡住）。使用卡牌時依「這張牌做了什麼」分 15 類主題演出（流星雨、酸雨、爆炸、得分星星、閃電、治療光柱、吸取、空降、額外回合、防禦罩、骰子、羽毛、復活光柱…），卡面（名字、費用、效果）會飄在使用者旁邊；持有的保留卡（護甲、吸血、反射、得分加成…）被動發動時也會演一個輕量特效（卡面小浮現＋主題色光點），煙霧彈有專屬的煙幕。右上角提示**不分敵我**：任何人使用或發動卡牌都會寫「誰、哪張牌、造成什麼」——對所有人的 HP／⭐／⚡ 變化、多一次擲骰機會、改骰、額外回合、指示物等；沒有可量化影響的被動卡就顯示卡面文字，讓你也能認識沒用過的卡。飛碟用鏡頭空間定位並另外疊一層渲染（不被建築擋住、不論鏡頭怎麼跟都在畫面上半部）。純視覺，可在場景下方取消勾選「商店飛碟與卡牌特效」（系統「減少動態」時預設關閉）。
- **卡牌說明跟著動作走（M4.21）：** 按鈕上只寫得下卡名，所以凡是動作牽涉到「別的卡牌」，旁邊都會列出那張牌的名稱、費用與卡面文字——買變色龍之眼時每個可複製的牌、複製／賣掉（變形）的對象、讓位時可以拿走的牌、可使用的防禦牌，以及機會主義者剛翻開的那張牌（以前只寫「買下這張牌」，看不出是哪張）。
- **設定面板與離線單機（M4.11）：** HUD 分頁新增「⚙ 設定」（3D 開關、畫質、鏡頭、各種特效；之後的彈幕與新手教學也放這裡），全螢幕與「關閉 3D」放在 3D 場景右上角（橫向排列；縮放與鏡頭按鈕在右下）。登入頁新增「玩法」選擇（線上房主模式／離線單機／伺服器模式），不必再手打網址參數。離線單機加上 Service Worker：**第一次必須連網載入頁面**，載入完成後頁面與全部程式存進瀏覽器，之後完全沒有網路也能開啟並玩離線單機（先前只有已經開著的分頁能繼續玩，重新整理就打不開）。
- **關於分頁（M4.22）：** HUD 第 8 個分頁「ℹ 關於」：一句話介紹、作者、版權聲明（非官方粉絲專案；機制參考《King of Tokyo》，怪獸與卡面為原創）與 GitHub 連結。八個分頁排成整齊的 4×2。
- **保護色的擲骰看得見（M4.23）：** 受傷時每 1 點傷害擲 1 顆骰子、擲出 ❤️ 免除，這個規則一直是對的，但擲骰過程原本沒有任何事件——沒擲出 ❤️ 時完全沒有提示，看起來像沒擲。現在每次都會留下 `card_rolled` 事件並跳提示（「擲出 1 💥 ❤️；你擋下 1 點傷害」「擲出 2 ⚡（沒有 ❤️）」）。
- **聊天與彈幕（M4.14）：** HUD 新增「💬 聊天」分頁（大廳以外的對局中使用，未讀數顯示在分頁上）。3D 開著時，新訊息會變成**彈幕**：從場景右上飛入、左上飛出，文字是發話玩家的顏色（半透明），同一軌道不重疊。「⚙ 設定」可開關彈幕、用拉桿調文字透明度（20–100%）、大小（14–40px）與移動速度（0.4–3 倍，1 倍約 9 秒飛過畫面），並有預覽按鈕；設定存在這個瀏覽器。聊天只在房內廣播（每人每 0.6 秒一則、80 字、不含換行），**不存檔、不進對局紀錄**，重新整理就沒有歷史；離線單機、房主模式與伺服器模式都能用（協定版本不變）。
- **勝利演出（M4.15）：** 勝負一分，勝者頭上戴上金色皇冠（依各怪獸頭的大小縮放、跟著頭轉），3D 場景持續撒彩帶、噴金色光點、放金色衝擊波，偶爾咆哮；**所有人**的鏡頭鎖定勝者、繞著他慢慢轉（多位勝者每 7 秒換一位；拖曳過的視角與「跟隨」開關都會被鎖回；系統「減少動態」時不動鏡頭，只保留皇冠與特效）。全螢幕時頁面上的橫幅看不到，所以場景上方中間另有「👑 勝者：…」提示。
- **持續性狀態特效（M4.17）：** 怪獸身上有指示物時，3D 場景會一直演出對應的效果（狀態驅動，指示物消失就停）。**中毒**：紫綠色毒霧從腳下升起、繞著怪獸打轉並冒小氣泡，身體紫綠閃爍，指示物越多霧越濃；**縮小**：青白色光點盤旋收向怪獸，怪獸本身縮成原來的一半（0.5×，與指示物數量無關）。名牌（怪獸頭上的狀態卡）下方會多一排圖示 ☠×N（中毒）、🤏×N（縮小），HUD 的玩家列表與「我的卡牌」也加了圖示。特效全部程式繪製（單一 Points、一次 draw call 一種、數量固定），跟著「商店飛碟與卡牌特效」開關（系統「減少動態」時預設關閉；關閉時名牌圖示仍在）。
- **新手教學（M4.19）：** 第一次進遊戲會跳出 6 張「快速規則」投影片（目標、擲骰、骰面結算、東京、買牌、看懂畫面），可上一步／下一步／跳過；若正好輪到你，會先讓你玩、等不是你的回合再跳出（對話框開著時回合計時仍在走）。之後第一次遇到某個時機（輪到你擲骰、東京被攻擊要不要讓位、分配治療、買牌階段）會在左下角跳出一張情境提示，按「知道了」才算看過、不再出現。「⚙ 設定 → 📘 新手教學」可以關閉、「重看快速規則」、「重置提示」；是否開啟與看過哪些存在瀏覽器（localStorage `kot.tutorial.v1`），下次記得。全螢幕時也會顯示。
- **東京加分與「在東京補不了血」提示（M4.24）：** 進入東京 +1 ⭐（R-TOKYO-03）、回合開始仍在東京 +2 ⭐（R-TURN-02）原本只有 3D 飄字，現在 🗼 提示也寫出加分（「Bob進入東京市，+1 ⭐」「Bob佔領著東京，回合開始 +2 ⭐」，所有人可見）。在東京擲骰時，骰面 ❤️ 會變暗並打上 🚫、骰子區出現提醒；鎖定（保留）❤️ 時變成紅色警告。持有治癒光束、且場上有受傷又付得起能量的對象時，卡牌能力不受「在東京內骰子補血無效」限制（R-HEAL-02）：自己仍不能補，但 ❤️ 可以治療別的怪獸（東京內的也可以），骰面不標成無效。
- **12 種怪獸（M4.10）：** 蜥蜴、巨猿、機甲、章魚人、巨蟹、飛龍＋新增的巨龜、螳螂、雪怪、石魔、蘑菇怪、獨眼怪，各有自己的招式（巨龜水柱、螳螂鐮刀斬、雪怪冰霜、石魔震地、蘑菇怪孢子、獨眼怪凝視光束）。每場開局由伺服器隨機分配（純外觀，不影響規則，也不使用機密的對局 seed），透過房間狀態同步，所有人看到的一致；玩家列表會顯示每個人的怪獸名稱。
- **邀請連結（M4.12）：** 房間頁有「複製連結」（手機另有系統分享）。朋友點開 `https://網址/?room=房號`，輸入暱稱就會自動加入該房間；房號不存在或已滿時回到大廳並顯示原因。**離線單機不顯示邀請連結**：那個房間只存在這個分頁，別人點連結進不來。
- **電腦玩家（M4.13）：** 房主在房間頁按「🤖 加入電腦」（真人＋電腦最多 6 位，一個真人加一台電腦就能開局）。電腦由伺服器出手，不受逾時代管限制，行動前會停約 1.4 秒讓 3D 演出跟上。策略（`smartBot`）只看玩家看得到的資訊，用規則引擎本身試算每個選擇——擲骰時對所有保留方式做期望值計算、買牌與讓位時比較結算後的局面。它是啟發式策略，**不是可證明的最佳解**；對簡單機器人的實測勝率見 [architecture.md](docs/architecture.md)。
- **閒置踢除（M4.14）：** 連線一段時間沒有任何操作（滑鼠、鍵盤、觸控、遊戲動作）就會被伺服器中斷（預設 10 分鐘，試玩版 image 5 分鐘；`IDLE_KICK_MS`，0＝不踢）。畫面會出現「重新連線」，身分與座位保留。目的：開著網頁就離開的分頁不再一直佔著 Cloud Run 執行個體的計費時間。
- **離線模式（M5）：** 開 `/?mode=offline`（或 `/?offline=1`；本機開發：`http://localhost:5173/?mode=offline`），不連伺服器，在這個分頁裡加入電腦玩家就能玩完整局；重新整理會結束這局。
- **房主模式（M6，現在是預設）：** 直接開網址（等同 `/?mode=p2p`），不填房號登入就是房主（房間在你的瀏覽器裡執行，伺服器只轉送訊息）；把「分享連結」傳給朋友，或讓朋友在登入畫面輸入房號。畫面上方的紅色「房主模式」說明（含角色、連線方式、公平與信任說明、稽核結果）**預設收合成一行**，摘要仍會顯示角色與稽核結論（✅／⚠️／❌），點一下展開，展開狀態會記在這個瀏覽器。**伺服器權威模式**改用 `/?mode=server`（伺服器跑房間、可嚴格防作弊；邀請連結會保留 `mode=server`）。
- **直連（M7）：** 房主模式下，房主與玩家會在背景嘗試 WebRTC 直連（成功後訊息不再經過伺服器，畫面會顯示「與房主直連」）；所有人都直連且對局進行中時，房主連伺服器的連線也會暫停，伺服器只保留房號。連不上就維持經伺服器轉送，不影響遊戲；不使用 TURN。預設用 Google 的 STUN 查詢公開位址（對方會看到你的 IP），可用 `VITE_ICE_SERVERS` 更換或留空、網址加 `&direct=0` 關閉。直連中斷時會回到中繼並用原身分接回座位。
- **重整接回與韌性（M8）：** 房主模式下，房主**重新整理頁面**會從瀏覽器的存檔（IndexedDB，只存動作日誌與雜湊後的身分，24 小時後清除）還原同一局並用原房號重新登記，對局由系統暫時代打 20 秒讓大家接回；客人**重新整理**也會用原身分接回座位（房主同時重新整理也可以）。關閉分頁或主動離開則是結束這局。其他：對局中保持螢幕開啟（Wake Lock；不支援時提醒房主別讓螢幕休眠）、客人／伺服器模式顯示連線品質（往返時間）、漏了訊息時自動要求房主重送完整狀態（版本跳號、決策時間過了沒動靜、分頁回到前景）。**限制：** 房主頁面被強制關閉當下尚未寫入的最後一兩步會遺失（還原後以存檔為準）；還原後 3D 場景可能略過少數動畫。
- **房主轉移（M9）：** 房主模式下，房主關分頁、斷網或當機時，**第一順位的客人約 10 秒後自動接手成為新房主**（第 k 順位等 10＋(k−1)×3 秒，由伺服器時鐘裁決；接手金鑰只有本人持有，伺服器只存雜湊），所有人以原身分接回座位、對局從房主最後同步的狀態繼續；舊房主回來會降級成客人。房主也可按「交給○○」**主動交接**（約 1～2 秒，不中斷）。畫面顯示「你是房主／第 N 順位後備房主」。**限制：** 後備的複本只在記憶體（後備分頁重新整理會失去接手資格）；複本可能落後最後幾步（畫面倒退）；房主消失的約 10 秒內對局凍結；所有後備同時失聯則房間關閉；沒有分頁隱藏自動交接；後備持有完整複本（含種子），信任等級仍是「朋友之間」；真機、跨網路、手機背景化**未實測**。
- **種子共同產生與賽後稽核（M10）：** 房主模式下，按「開始」時**種子由房主與所有真人客人共同產生**（commit–reveal：房主先公布承諾 `H(房號, 次數, r_h)`，各客人把自己的亂數 `r_i` **只回給房主**，種子＝`H(房號, 次數, r_h, 依玩家 id 排序的 r_i)`），房主看到客人的亂數之前就已承諾，所以**無法單方面挑選骰子與牌序**，只能「重來」（次數會被記錄）；客人亂數不會廣播（廣播等於種子公開、隱藏資訊就沒有了）。局後每位客人的瀏覽器在背景 Worker **重放整場**，核對：承諾與揭露對得上、自己的亂數有被算進去、種子確實由此算出、動作日誌每一步合規、**對局中房主給我的每一個畫面都與規則重放的結果一致**；結果顯示在畫面上（✅ 通過／⚠️ 種子來源無法驗證／❌ 未通過並列出原因）。房主換人（M9）後，新房主帶著儀式紀錄，其他客人照常稽核。畫面常駐「關於公平與信任」說明。**限制（請照實理解）：** 這是**留下證據**，不是防作弊——每位客人都是後備房主、手上有種子，**偷看牌庫順序無法阻止**，信任等級是「朋友之間」，要嚴格防作弊請用伺服器模式；稽核抓得到「畫面與日誌被改」，抓不到「只偷看」；每位客人只稽核自己看過的畫面（客人之間不互相驗證，房主對不同人說謊會被各自抓到）；重新整理過的客人沒有參與記錄，只檢查房主自己的承諾；逾時（5 秒）沒回應的客人（舊版）不在種子裡，列為缺席；單人加電腦的房間沒有儀式；選配的複本加密遮蔽**沒有做**（理由見 [ADR-0007](docs/adr/0007-p2p-host-authoritative.md) §3.1：金鑰必須在同一瀏覽器，只擋得住隨手開 DevTools）；真機、跨網路、手機背景化**未實測**。
- **尚未有：** 上線整備（M11）；P2P 架構的完整計畫見 [ADR-0007](docs/adr/0007-p2p-host-authoritative.md)。3D 效能目前只在沙盒（軟體算圖）量過，基準機實測見 [runbook](docs/runbooks/mac-verification.md)。直連只在沙盒的同機 Chromium 驗證過，真實跨網路、手機、Safari／Firefox 都**未實測**。

進度、里程碑與驗證狀態見 [docs/architecture.md](docs/architecture.md)。

## 快速開始

需要 Node 22 與 pnpm（`corepack enable` 會依 `packageManager` 安裝正確版本）。

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm run dev:server    # 遊戲伺服器 http://localhost:3001（/healthz 可檢查）
pnpm run dev:web       # 網頁 http://localhost:5173
```

開兩個瀏覽器視窗（其一用無痕），各輸入暱稱；一邊建房，另一邊輸入房號加入並按「準備」，房主開始。

不連伺服器看 3D 場景：開 `http://localhost:5173/?scene-demo`（離線展示頁，可手動觸發各種演出、切換畫質）。

**試玩版（單一容器，可部署到 Cloud Run）：** `make demo-image` 建置、`make demo-run` 在本機試跑（http://localhost:8080）。伺服器直接提供網頁，房間全在記憶體、沒有資料庫，同時最多 5 個房間、30 個連線，**大廳不顯示「伺服器模式」**（伺服器也拒絕，避免耗用免費額度），只含原創卡組。只有明確執行 `make demo-image` 才會建置。部署與預算警示步驟見 [docs/runbooks/cloud-run-demo.md](docs/runbooks/cloud-run-demo.md)（**未實測**）。

或用 Docker（完整開發環境，含 PostgreSQL；目前遊戲本身還沒用到資料庫）：

```bash
cp .env.example .env            # 並修改 POSTGRES_PASSWORD
docker compose up --build
```

## 常用指令

```bash
pnpm run check                                           # 提交前必跑：基準機檢查、格式、lint、型別、測試、建置
pnpm run test                                            # 全部測試
pnpm --filter @kot/rules run play -- --players 4 --seed 7   # 規則引擎文字版（機器人對戰）；加 --games 500 看統計
pnpm --filter @kot/rules run arena -- --players 4 --games 200 --vs greedy   # 電腦玩家（smartBot）對戰量測
pnpm --filter @kot/cardsets run import                   # 把 card-sets/local/ 內的官方卡表 CSV 轉成 set.json
```

### 使用自備卡表

先建立資料夾並放入卡表 CSV：`mkdir -p card-sets/local && cp <卡表>.csv card-sets/local/`（該目錄不會被提交，也不會進 Docker 映像），再執行上面的 `import` 指令產生 `set.json`，重啟伺服器後，建房時就會多一個卡牌組選項，且成為預設值。沒有放時只提供原創卡組。Docker 開發環境會自動把 `card-sets/` 以唯讀方式掛進 server 容器。

## 結構

```
packages/rules      純規則引擎（無 I/O、可重現、前後端共用）
packages/protocol   WebSocket 訊息型別與 zod 驗證
packages/cardsets   卡牌組驗證、載入、雜湊與 CSV 匯入（`@kot/cardsets/pure` 是瀏覽器可用的部分）
packages/room       房間、連線閘道、計時、電腦玩家（不依賴 node:*，伺服器與瀏覽器 Worker 共用）
apps/server         Fastify + Socket.IO：身分、房間、計時，呼叫 rules
apps/web            Vite + React 前端；src/scene/ 是 Three.js 場景（動態載入）、src/hud/ 是遊戲 HUD 與說明提示
card-sets/          卡牌組資料（original 提交；官方卡表只放 local/，不提交）
```
